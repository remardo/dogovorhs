# Исправление учёта после аудита

Авторизация и параметры защиты доступа остаются без изменений по прямому указанию пользователя. Нельзя менять REQUIRE_AUTH, добавлять login или ограничивать действующий доступ в этой задаче.

Цель: полный учёт начислений по договору, номеру, компании и историческому ответственному, с исходными документами, без двойного учёта общего счёта и детализации.

## Модель

- Добавочные, необязательные поля существующих таблиц; действующие записи и оригиналы сохраняются.
- Расходы различаются как начисление (`charge`) и распределение (`allocation`). Отсутствие признака у legacy-расхода означает charge. Общие финансовые итоги включают только charge; персональные/номерные срезы — allocation и непосредственно номерные charge, без повторного суммирования.
- Добавить устойчивые ссылки contractId, simCardId, employeeId, invoiceId, parentExpenseId, periodKey (`YYYY-MM`), periodStart/End и snapshot исторического ответственного там, где требуется. Старые текстовые поля сохранить для совместимости и исходного документа.
- SIM прямо связан с договором. `simAssignments` сохраняет employeeId и интервал выдачи/снятия. Нельзя приписывать прошлое начисление текущему владельцу: если историческое назначение неизвестно/неоднозначно, оно остаётся нераспределённым.
- Ответственный за договор и адрес подключения — optional. Счётчики SIM вычисляются, а не вводятся вручную.

## Сервер

- Применение счёта + charge одной mutation. Проверка повторного fileId/fingerprint и документного ключа. Идентифицировать документ не только по договору/месяцу. Смена договора синхронизирует charge и allocations атомарно; конфликт с документом/назначениями требует явного решения.
- Детализация создаёт allocations с прямыми ссылками. Если подходящий charge уже есть, прикреплять только при однозначности и сверке сумм; не увеличивать общую сумму. Если счёта нет, создавать один aggregate charge на договор/период и его allocations; поздний счёт присоединяется к нему только при однозначной сверке. Разные счета одного договора за месяц не схлопывать.
- Применённый importId не применяется повторно и не возвращается в preview; повтор файла с другим именем определяется hash. Нужны отчёт о сверке и возможность видеть нераспределённый остаток/несовпадение.
- Источники документов не уничтожать при обычном удалении: аннулировать записи с причиной/датой, исключая их из активных сумм, сохраняя историю. Используемые справочники/договоры не удалять физически. Ручные корректировки имеют явное основание.
- Серверные проверки связей, периода, округления денег/сумм и назначений: сотрудник компании, активность, тариф оператора, лимит, явное снятие null. Согласованные правила НДС по документу; никаких догадок по текущему законодательству.
- Сделать dry-run + применяемую добавочную migration/backfill с отчётом неоднозначностей; никаких resets/seed production. Журнал событий изменений финансовых записей и назначений.
- Итоги/периоды корректны для полной выбранной выборки, не обрезать скрыто до 5000. Минимальная пагинация для реестра/истории по необходимости.

## UI

- Исправить слой запросов: native Convex reactive hooks/provider; ошибки mutation пробрасываются и не превращаются в success. Отдельные loading/error/empty.
- Один фильтр service-period на всех сводках; календарная сортировка, пустой период = 0; убрать фиктивные проценты и недействующие переключатели.
- Единое открытие карточки через ссылку/номер/название, возможность `?id=...` и переходов из поиска. Вторичные действия остаются в меню. Компании/операторы/тарифы получают реальные просмотр/редактирование.
- Карточки договоров, SIM, сотрудников показывают историю начислений и исходные документы с периодами и итогами. История выдачи SIM, ответственный договора/адрес, назначение/снятие.
- Счета: фильтры, редактируемый предпросмотр суммы/НДС/периода/номера, вид invoice/detail, согласованный выбор договора/компании, результаты каждого файла, без потери всего пакета при ошибке одного.
- Расходы: номер договора/номер SIM вместо '-', документ-основание, charge/allocation и сверка понятны пользователю без технических терминов. Не считать allocation общим расходом повторно.
- Свернуть sidebar на узком экране, прокручивать таблицы локально, доступные имена icon-кнопок и клавиатурные ссылки.
